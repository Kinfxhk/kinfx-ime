# v0.5 中英混打設計（English smart mode）

狀態：設計稿，2026-10-16。v0.5 已依「方案 E」實作（見 STATUS.md）；
本文件保留量度數據和決策理由。

## 目標

- 打字途中可以直接出英文，包括短詞（is、am、of、OK）。
- 速成中文照常用 1–9 選字。
- 不必切換模式。
- 頭 9 個候選永遠與 Windows 11 微軟速成一致。

## Kaiboard 怎樣做（參考）

資料來源：kaiboard.app 功能介紹及幫助中心、App Store 說明及評論、LIHKG 討論串 3638116。

| 行為 | Kaiboard |
| --- | --- |
| 預設 | 字母當英文；選字欄同時顯示中文候選；選了才變中文 |
| 英文上屏 | 按空白（英文＋空格） |
| 英文之後打中文 | 先按空白或者 Ⓧ，再打中文碼 |
| 空白鍵 | 「又可以轉頁，又可以輸入空白」 |
| 頂字 | 沒有（觸控鍵盤，沒有第 3 碼頂字） |
| 用戶投訴 | 中英之間要加空格；Ⓧ 太易誤按 |

Kaiboard 是「英文優先，中文要選」。Windows 速成是「中文優先，第 3 碼頂字」。兩者方向相反，不可以原樣搬過來。

## 數據

### 短英文詞全部是速成碼

28 個常用短詞之中，26 個是兩碼速成碼，`a`、`i` 是單碼。例如 `is`＝成、`of`＝伙、`or`＝合、`ok`＝仗、`hi`＝凡。也就是說，**短英文無法自動判斷是中文還是英文**，一定要靠一個鍵告訴輸入法。

### 空白鍵：何時可以安全地上屏英文

模擬方法：用 `essay-cantonese.txt` 字頻抽樣 566,133 個中文字，每個字用 Windows 最少按鍵的打法打（字母、翻頁空白、數字）。假設保留的字母是某個英文詞時，空白鍵就上屏英文。數一數會改變多少次 Windows 結果。

英文詞表：wordfreq 英文最常用詞。

| 空白鍵上屏英文的條件 | 詞表 | 每 1 萬個中文字改變多少次 | 最常撞 |
| --- | --- | --- | --- |
| 2 個字母或以上 | 頭 3,000 | 334 | or、hi、ok、on、re |
| 3 個字母或以上 | 頭 3,000 | 0.69 | door、sure、mark |
| 3 個字母或以上 | 頭 20,000 | 2.3 | bros、odor、door、dorm |
| 5 個字母或以上 | 頭 20,000 | **0** | — |
| 標點緊接英文（3 個字母或以上） | 頭 20,000 | 0.2 | haha、jojo |

結論：
- 2 個字母的英文詞絕對不可以用空白自動上屏（每 30 個字就撞一次）。
- 3–4 個字母撞得很少，但不是 0。
- 5 個字母或以上 0 次改變。

### Windows 本身如何使用 Shift

本機微軟速成：左 Shift 用途＝0，右 Shift 用途＝1。KINFX 現在：左 Shift＝臨時英文，右 Shift＝上屏候選（`is` 右 Shift → 成）。

## 觸發鍵（2026-10-16 第二輪）

用戶意見：右 Shift 太遠，不接受。重新比較左手可用的鍵和非按鍵方法。

### 先減少要按鍵的次數：逐詞計「空白安全度」

不再用「5 個字母或以上」一刀切，改為逐個英文詞計：如果空白鍵用來上屏這個英文詞，平均每 1 萬個中文字會改變多少次 Windows 結果（`tools/design/rate_words.py`，按 essay-cantonese 單字和雙字頻率計，與 56.6 萬字模擬對過數字，量級一致）。

| 門檻（每 1 萬字） | 可以直接用空白的詞 | 佔英文用字比例 | 每 1 萬中文字改變 |
| --- | --- | --- | --- |
| 只限 5 個字母或以上 | — | 37% | 0 |
| ≤ 0.001 | 5 字母以上＋2,664 個短詞 | 77% | 0.12 |
| **≤ 0.01（建議）** | 5 字母以上＋2,801 個短詞 | **80%** | **0.6（約每 1.6 萬字一次）** |
| ≤ 0.05 | 5 字母以上＋2,886 個短詞 | 83% | 2.8 |

也就是說，`the`、`and`、`you`、`for`、`are`、`app`、`team`、`idea`、`is`、`i`、`by`、`an` 都可以直接用空白上屏。仍然要按鍵的主要是常用兩字母詞：to of in it on be as at he my or we so me if do no go am，以及少數 3–4 字母（give、sure、hard、door）。

Linux VM 實測文章 29 個細楷英文詞：28 個屬於「直接空白」，只有 `of` 要按鍵。

### 左手鍵比較

| 鍵／方法 | 順手程度 | 與速成或者系統會否衝突 | 學習 | 結論 |
| --- | --- | --- | --- | --- |
| **左 Shift 按一下** | 小指，最常用的修飾鍵 | 不與速成衝突；Shift＋字母（大寫）和「按一下」librime 分得開；Windows 微軟速成本身也用 Shift 切換中英 | v0.4.1 文件已經教「Shift＝英文」 | ✅ 預設 |
| Caps Lock | 小指，中排 | 會改 OS 大小寫狀態和燈號；`good_old_caps_lock` 已用來打大寫 | 中 | 🟡 可選 |
| Tab | 小指，上排 | 現在用來展開註釋；部分程式 Tab 會跳格 | 中 | ❌ |
| 左 Ctrl／Alt 按一下 | 一般 | 很多程式捷徑；Alt 按一下會開菜單 | 高 | ❌ |
| 雙擊空白 | 很順手 | 空白本身要翻頁，雙擊等於翻兩頁 | 低 | ❌ |

| 「英文模式黏著」（打完英文，下一個詞也當英文） | 0 個鍵 | 每次由英文轉回中文，約 19.6% 機會撞（os、or、yu、ru…） | 低 | ❌ |

### Kaiboard 用戶怎樣切換

- 英文上屏：按空白（英文＋空格）。
- 英文之後打中文：按空白或 Ⓧ，或者向上掃選字欄，然後才打中文碼。
- LIHKG 用戶投訴：「中英切換中間要有個空格」；App Store 投訴 Ⓧ 太易誤按。

也就是說 Kaiboard 也是「空白上屏英文」，只是它沒有速成頂字，所以短詞沒有衝突。我們用逐詞安全度表解決短詞問題。

## 方案比較

| 方案 | 短詞（1–2 個字母） | 長詞 | 對 Windows 結果的影響 | 中文按鍵成本 |
| --- | --- | --- | --- | --- |
| A. v0.4.1 現在：左 Shift | 前後各按一下 Shift | 同左 | 0 | 0 |
| B. Kaiboard 原樣 | 字母＋空白 | 字母＋空白 | 沒有第 3 碼頂字、沒有空白翻頁 | 約 23% 的字要額外按數字（第 1 候選兩碼字 128,297／566,133） |
| C. 延遲頂字＋左 Shift（上一版提案） | 前後各按一下 Shift | 字母＋Shift | 0 | 0 |
| D. 智能空白＋右 Shift（第一輪） | 字母＋右 Shift | 字母＋空白（5 個字母或以上） | 0 | 0 |
| **E. 智能空白（逐詞）＋左 Shift（建議）** | 80% 用字直接空白；常用兩字母詞＋左 Shift | 字母＋空白 | 約每 1.6 萬字一次（可調到 0） | 0 |

## 建議：方案 E

| 鍵 | 作用 |
| --- | --- |
| 字母 | 照 Windows 打速成。已輸入的字母仍是英文詞開頭時，第 3 碼頂字延遲：預編輯照顯示 Windows 結果，尾部顯示英文提示 |
| 1–9 | 永遠選中文，頭 9 個與 Windows 一樣 |
| 空白 | 保留的字母是「空白安全」英文詞：上屏英文＋空格。其他情況：照 Windows 翻頁 |
| **左 Shift 按一下** | 有保留的字母：當英文上屏（`of` 左 Shift → of），之後立即返回中文，不必再按。沒有字母：照舊切換臨時英文 |
| 標點 | 保留的字母是空白安全英文詞：上屏英文＋標點 |
| `=`／Page Down | 永遠翻頁（空白被英文占用時的後備） |
| 右 Shift | 維持不變（上屏中文第 1 候選） |

用戶要學的：「英文照打，按空白；兩個字母的短詞，按左 Shift。」預編輯會用 `⇧` 提示哪些詞要按 Shift。

每個英文詞的額外成本：80% 用字 0 個；其餘 1 個（左 Shift）。v0.4.1 是每個詞 2 個。

### Linux

Fcitx5 預設用左 Shift 切換輸入法，會先攔截這個鍵。要在 VM 實測：
1. fcitx5-rime 切換離開時會不會將保留的字母當英文上屏（如果會，效果已經接近）。
2. 不會的話，`install-linux.sh` 問用戶後解除 Fcitx5 左 Shift 熱鍵，或者 Linux 預設改用 Caps Lock（`commit_key: Caps_Lock`）。

## 要再驗證

1. 離線比對工具：用 Windows 頂字做對照，逐個比對兩碼＋兩碼、三段連打的最後輸出，要求 0 改變（空白規則那幾次除外，要逐個列出）。
2. 左 Shift 按一下：有保留字母時用 Lua 上屏原字母、不切換模式（`ascii_composer` 的 `commit_code` 會切去英文模式，不適用）。
3. Backspace：延遲頂字期間，逐個刪除，與 Windows 一樣。
4. 英文詞表：用 SCOWL（已經在 repo）還是 wordfreq（Apache-2.0 程式；詞頻數據 CC BY-SA 4.0）要查看授權。
5. 真機：Windows 11 小狼毫、Linux Fcitx5 各自實打。

## 開關

```yaml
english:
  mode: smart        # smart | shift | off
  space: safe        # safe（逐詞安全表）| long（只限 5 個字母或以上，0 改變）| off
  safe_max: 0.01     # 每 1 萬中文字容許改變次數
  commit_key: Shift_L # 可改 Caps_Lock
```

`shift`＝v0.4.1 行為；`off`＝沒有英文提示。
