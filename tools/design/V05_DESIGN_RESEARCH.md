# v0.5 中英混打設計（English smart mode）

狀態：設計稿，2026-10-16。v0.5 已依「方案 E」實作（見 STATUS.md）；
本文件保留量度數據同決策理由。

## 目標

- 打字途中可以直接出英文，包括短詞（is、am、of、OK）。
- 速成中文照常用 1–9 揀字。
- 唔使切換模式。
- 頭 9 個候選永遠同 Windows 11 微軟速成一致。

## Kaiboard 點做（參考）

資料來源：kaiboard.app 功能介紹及幫助中心、App Store 說明及評論、LIHKG 討論串 3638116。

| 行為 | Kaiboard |
| --- | --- |
| 預設 | 字母當英文；選字欄同時顯示中文候選；揀咗先變中文 |
| 英文上屏 | 撳空白（英文＋空格） |
| 英文之後打中文 | 先撳空白或者 Ⓧ，再打中文碼 |
| 空白鍵 | 「又可以轉頁，又可以輸入空白」 |
| 頂字 | 冇（觸控鍵盤，冇第 3 碼頂字） |
| 用家投訴 | 中英之間要加空格；Ⓧ 太易誤撳 |

Kaiboard 係「英文優先，中文要揀」。Windows 速成係「中文優先，第 3 碼頂字」。兩者方向相反，唔可以原樣搬過嚟。

## 數據

### 短英文詞全部係速成碼

28 個常用短詞入面，26 個係兩碼速成碼，`a`、`i` 係單碼。例如 `is`＝成、`of`＝伙、`or`＝合、`ok`＝仗、`hi`＝凡。即係話，**短英文冇得自動判斷係中定英**，一定要靠一粒鍵話畀輸入法知。

### 空白鍵：何時可以安全咁上屏英文

模擬方法：用 `essay-cantonese.txt` 字頻抽樣 566,133 個中文字，每個字用 Windows 最少按鍵嘅打法打（字母、翻頁空白、數字）。假設留住嘅字母係某個英文詞時，空白鍵就上屏英文。數一數會改變幾多次 Windows 結果。

英文詞表：wordfreq 英文最常用詞。

| 空白鍵上屏英文嘅條件 | 詞表 | 每 1 萬個中文字改變幾多次 | 最常撞 |
| --- | --- | --- | --- |
| 2 個字母或以上 | 頭 3,000 | 334 | or、hi、ok、on、re |
| 3 個字母或以上 | 頭 3,000 | 0.69 | door、sure、mark |
| 3 個字母或以上 | 頭 20,000 | 2.3 | bros、odor、door、dorm |
| 5 個字母或以上 | 頭 20,000 | **0** | — |
| 標點緊接英文（3 個字母或以上） | 頭 20,000 | 0.2 | haha、jojo |

結論：
- 2 個字母嘅英文詞絕對唔可以用空白自動上屏（每 30 個字就撞一次）。
- 3–4 個字母撞得好少，但唔係 0。
- 5 個字母或以上 0 次改變。

### Windows 自己點用 Shift

本機微軟速成：左 Shift 用途＝0，右 Shift 用途＝1。KINFX 而家：左 Shift＝臨時英文，右 Shift＝上屏候選（`is` 右 Shift → 成）。

## 觸發鍵（2026-10-16 第二輪）

用戶意見：右 Shift 太遠，唔收貨。重新比較左手可用嘅鍵同非撳鍵方法。

### 先減少要撳鍵嘅次數：逐詞計「空白安全度」

唔再用「5 個字母或以上」一刀切，改為逐個英文詞計：如果空白鍵用嚟上屏呢個英文詞，平均每 1 萬個中文字會改變幾多次 Windows 結果（`tools/design/rate_words.py`，按 essay-cantonese 單字同雙字頻率計，同 56.6 萬字模擬對過數，量級一致）。

| 門檻（每 1 萬字） | 可以直接用空白嘅詞 | 佔英文用字比例 | 每 1 萬中文字改變 |
| --- | --- | --- | --- |
| 只限 5 個字母或以上 | — | 37% | 0 |
| ≤ 0.001 | 5 字母以上＋2,664 個短詞 | 77% | 0.12 |
| **≤ 0.01（建議）** | 5 字母以上＋2,801 個短詞 | **80%** | **0.6（約每 1.6 萬字一次）** |
| ≤ 0.05 | 5 字母以上＋2,886 個短詞 | 83% | 2.8 |

即係話，`the`、`and`、`you`、`for`、`are`、`app`、`team`、`idea`、`is`、`i`、`by`、`an` 都可以直接用空白上屏。仍然要撳鍵嘅主要係常用兩字母詞：to of in it on be as at he my or we so me if do no go am，同埋少數 3–4 字母（give、sure、hard、door）。

Linux VM 實測文章 29 個細楷英文詞：28 個屬於「直接空白」，只有 `of` 要撳鍵。

### 左手鍵比較

| 鍵／方法 | 就手 | 同速成或者系統撞唔撞 | 學習 | 結論 |
| --- | --- | --- | --- | --- |
| **左 Shift 撳一下** | 小指，最常用嘅修飾鍵 | 唔撞速成；Shift＋字母（大寫）同「撳一下」librime 分得開；Windows 微軟速成本身都用 Shift 切中英 | v0.4.1 文件已經教「Shift＝英文」 | ✅ 預設 |
| Caps Lock | 小指，中排 | 會改 OS 大小寫狀態同燈號；`good_old_caps_lock` 已用嚟打大寫 | 中 | 🟡 可選 |
| Tab | 小指，上排 | 而家用嚟展開註釋；部分程式 Tab 會跳格 | 中 | ❌ |
| 左 Ctrl／Alt 撳一下 | 一般 | 好多程式捷徑；Alt 撳一下會開菜單 | 高 | ❌ |

### Kaiboard 用戶點切

- 英文上屏：撳空白（英文＋空格）。
- 英文之後打中文：撳空白或 Ⓧ，或者向上掃選字欄，然後先打中文碼。
- LIHKG 用家投訴：「中英切換中間要有個空格」；App Store 投訴 Ⓧ 太易誤撳。

即係 Kaiboard 都係「空白上屏英文」，只係佢冇速成頂字，所以短詞冇衝突。我哋用逐詞安全度表解決短詞問題。

| A. v0.4.1 而家：左 Shift | 前後各撳一下 Shift | 同左 | 0 | 0 |
| B. Kaiboard 原樣 | 字母＋空白 | 字母＋空白 | 冇第 3 碼頂字、冇空白翻頁 | 約 23% 嘅字要額外撳數字（第 1 候選兩碼字 128,297／566,133） |

## 建議：方案 E

| 鍵 | 作用 |
| --- | --- |
| 字母 | 照 Windows 打速成。打過嘅字母仲係英文詞開頭時，第 3 碼頂字延遲：預編輯照顯示 Windows 結果，尾部顯示英文提示 |
| 1–9 | 永遠揀中文，頭 9 個同 Windows 一樣 |
| 空白 | 留住嘅字母係「空白安全」英文詞：上屏英文＋空格。其他情況：照 Windows 翻頁 |
| **左 Shift 撳一下** | 有留住嘅字母：當英文上屏（`of` 左 Shift → of），之後即刻返中文，唔使再撳。冇字母：照舊切臨時英文 |
| 標點 | 留住嘅字母係空白安全英文詞：上屏英文＋標點 |
| `=`／Page Down | 永遠翻頁（空白被英文用咗嗰陣嘅後備） |
| 右 Shift | 唔郁（上屏中文第 1 候選） |

用戶要學嘅：「英文照打，撳空白；兩個字母嘅短詞，撳左 Shift。」預編輯會用 `⇧` 提示邊啲詞要撳 Shift。

每個英文詞嘅額外成本：80% 用字 0 粒；其餘 1 粒（左 Shift）。v0.4.1 係每個詞 2 粒。

### Linux

Fcitx5 預設用左 Shift 切輸入法，會先食咗呢粒鍵。要喺 VM 實測：
1. fcitx5-rime 切走時會唔會將留住嘅字母當英文上屏（如果會，效果已經接近）。
2. 唔會嘅話，`install-linux.sh` 問用戶後解除 Fcitx5 左 Shift 熱鍵，或者 Linux 預設改用 Caps Lock（`commit_key: Caps_Lock`）。

## 要再驗證

1. 離線比對工具：用 Windows 頂字做對照，逐個比對兩碼＋兩碼、三段連打嘅最後輸出，要求 0 改變（空白規則嗰幾次除外，要逐個列出）。
2. 左 Shift 撳一下：有留住字母時用 Lua 上屏原字母、唔切模式（`ascii_composer` 嘅 `commit_code` 會切去英文模式，唔啱用）。
3. Backspace：延遲頂字期間，逐粒刪，同 Windows 一樣。
4. 英文詞表：用 SCOWL（已經喺 repo）定 wordfreq（Apache-2.0 程式；詞頻數據 CC BY-SA 4.0）要睇授權。
5. 真機：Windows 11 小狼毫、Linux Fcitx5 各自實打。

## 開關

```yaml
english:
  mode: smart        # smart | shift | off
  space: safe        # safe（逐詞安全表）| long（只限 5 個字母或以上，0 改變）| off
  safe_max: 0.01     # 每 1 萬中文字容許改變次數
  commit_key: Shift_L # 可改 Caps_Lock
```

`shift`＝v0.4.1 行為；`off`＝冇英文提示。
